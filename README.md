# Selectel DNS Sync

Автоматическая синхронизация DNS-зон из BIND-формата в Selectel DNS Hosting (API v2).

## 🚀 Возможности

- ✅ Парсинг BIND-файлов зон
- ✅ Автоматическая авторизация через IAM-токены Selectel
- ✅ Кэширование токенов (24 часа)
- ✅ Поддержка всех основных типов записей: A, AAAA, CNAME, MX, TXT, SRV, NS
- ✅ Обработка мультизначных записей (несколько IP для одного имени)
- ✅ Умное сравнение существующих записей
- ✅ Режим безопасного обновления (без перезаписи)
- ✅ Поддержка директорий с несколькими зонами
- ✅ Корректная обработка `$ORIGIN` и `$TTL`
- ✅ Автоматическое исправление формата TXT-записей

## 📋 Требования

- Python 3.7+
- Аккаунт в Selectel с доступом к DNS Hosting
- Сервисный пользователь с правами на управление DNS

##  Установка

1. **Клонируйте репозиторий или создайте директорию проекта:**

```bash
mkdir bind_to_selectel_api_dns && cd bind_to_selectel_api_dns
```

2. **Создайте и активируйте виртуальное окружение:**

```bash
python3 -m venv .venv
source .venv/bin/activate
# Для Windows: .venv\Scripts\activate
```

3. **Установите зависимости:**

```bash
pip install -r requirements.txt
```

## ⚙️ Настройка

Создайте или переименуйте файл `config.json.example` в `config.json` в директории со скриптом:

```json
{
  "account_id": "ваш_номер_аккаунта",
  "project_name": "имя_проекта",
  "username": "имя_сервисного_пользователя",
  "password": "api_ключ_сервисного_пользователя",
  "overwrite_existing": false
}
```

### Параметры конфигурации:

| Параметр | Описание | Пример |
|----------|----------|--------|
| `account_id` | ID аккаунта Selectel (цифры) | `"654321"` |
| `project_name` | Имя проекта в облачной платформе | `"Default_PRJ"` |
| `username` | Имя сервисного пользователя IAM | `"DNS"` |
| `password` | Пароль сервисного пользователя | `"apikeyforuserdns"` |
| `overwrite_existing` | Перезаписывать существующие записи | `false` (по умолчанию) |

### Где найти данные:

1. **Account ID**: В панели управления my.selectel.ru (правый верхний угол)
2. **Project Name**: В панели управления облачной платформой
3. **Сервисный пользователь**: IAM → Сервисные пользователи (доступно владельцу аккаунта или пользователю с ролью `iam.admin`)

## 📖 Использование

### Базовый запуск:

```bash

python selectel_dns.py /путь/к/файлу/зоны

python selectel_dns.py ./dns/example.com
```


##  Примеры BIND-файлов

### Простая зона:

```bind
$TTL 3600
$ORIGIN example.com.
@       IN SOA  ns1.example.com. admin.example.com. (
                        2026091501 ; serial
                        10800      ; refresh
                        3600       ; retry
                        604800     ; expire
                        3600 )     ; minimum

        IN NS   ns1.example.com.
        IN NS   ns2.example.com.
@       IN A    192.168.1.1
www     IN A    192.168.1.1
mail    IN A    192.168.1.2
        IN MX 10 mail
```

### Зона с несколькими поддоменами:

```bind
$TTL 3600
@       IN SOA  ns1.example.com. admin.example.com. (
                        2026091501 ; serial
                        3600       ; refresh
                        600        ; retry
                        604800     ; expire
                        3600 )     ; minimum

        IN NS   ns1.example.com.
        IN NS   ns2.example.com.
        IN A    192.168.1.1
        IN MX 10 mail
        IN MX 20 mail2
        IN TXT "v=spf1 mx ~all"

$ORIGIN sub.example.com.
www     IN A    192.168.2.1
api     IN A    192.168.2.2
```

## 🐛 Возможные ошибки и решения

### Ошибка 401 Unauthorized

**Причина**: Неверные учётные данные или истёкший токен.

**Решение**:
1. Проверьте `config.json` на наличие лишних пробелов
2. Убедитесь, что пароль сервисного пользователя верный
3. Удалите `token_cache.json` для принудительной переавторизации

### Ошибка 422 Bad Request

**Причина**: Некорректный формат DNS-записи.

**Решение**:
- TXT-записи должны быть в двойных кавычках
- Для MX и SRV целевые хосты должны быть FQDN (с точкой или относительные)
- Проверьте синтаксис BIND-файла

### Ошибка 409 Conflict

**Причина**: Зона уже существует.

**Решение**: Это нормальная ситуация. Скрипт автоматически найдёт существующую зону и продолжит работу.

##  Продвинутые настройки

### Режим перезаписи существующих записей

В `config.json` установите:

```json
{
  "overwrite_existing": true
}
```

**Внимание!** Это приведёт к замене всех существующих записей в зоне на те, что указаны в BIND-файле.

### Ручное управление токеном

Если вы хотите использовать статический токен (не рекомендуется):

```bash
export SELECTEL_API_TOKEN="your_static_token"
```
